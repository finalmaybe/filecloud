# Filecloud 桌面客户端 PRD · 首版

**状态：已进入开发预览，正式发布验收未完成。** [实现与试用](../../desktop/README.md)。 基线：`eb3902c`（2026-11-22），此文保留首版范围；当前界面与交互以[桌面设计稿](desktop-mockups/filecloud-desktop-design.pdf)为准。配套：[技术方案](desktop-client-architecture.md) · [三端设计资料与取舍](../research/desktop-platform-design.md)。本文描述拟交付产品，正式排期按仓库 GitHub Issues 流程推进。

## 1. 给谁用，解决什么问题

给已有 Filecloud 账号、在不同电脑上编辑普通本地文件的人使用。用户今天能用 CLI 同步，但第一次绑定要选对目录、自动同步需要保持命令运行，遇到大量删除还要从终端核对候选。首版的成功标准是：用户不打开终端，就能把一个资料库安全绑定到本机，关窗继续工作，并知道何时需要自己作决定。

首发目标为 Ubuntu 24.04 / GNOME（amd64、本地 ext4）、Windows 11（amd64、本地固定 NTFS）、macOS（Apple Silicon、本地 APFS）。这些文件系统限制同时适用于客户端状态目录和工作目录。桌面具体支持的系统版本以真实安装包验收记录冻结。三端能力相同。

## 2. 用户的主路径

以下为首版主路径。新稿对三个平台共用一套任务视图，保留各平台原生窗口控件。

1. **「我的资料库」回答“我在同步哪里？”** 已绑定和未绑定分组。选中已绑定资料库，详情显示本机工作目录、打开目录和查看版本历史；未绑定行显示「绑定目录」。同名资料库按 ID 区分，遇到同名时展示可区分的短 ID。
2. **「最近活动」回答“刚才发生了什么？”** 显示此设备实际观察到的扫描、同步结果、错误及时间。当前需要处理的事项置顶，活动按时间倒序；「需要处理」的数量按仍受阻的绑定计，不按重试次数计。在这里可以直接打开工作目录。
3. **「核对删除影响」回答“同意会发生什么？”** 显示资料库、工作目录、待删除数、原跟踪总数。例：**82 / 240 个路径**，指已在本机消失、确认后将向资料库发布的删除，其他设备下次同步时接收。不是再删一遍本地文件。「查看影响」只打开说明；「暂不处理」保留待办；「确认同步删除」才授权当前这批变更。

## 3. 范围与行为

| ID / 优先级 | 交付给用户的行为 | 空态、失败与边界 |
|---|---|---|
| D1 · P0 登录与资料库 | 每次使用一个服务、一个当前账号。输入服务地址、账号、密码和设备名；登录后列自己的资料库，按页加载。没有资料库时可创建再绑定。 | 非回环地址要求 HTTPS。首次离线说明需联网登录；已有绑定时保留本机视图，远端目录标记未刷新。账号变更不展示上个账号的数据。 |
| D2 · P0 绑定与解绑 | 用系统目录选择器选普通本地目录。远端有版本时，可下载到空目录，或选择「和已有文件夹同步」，核对上传、下载和冲突文件后合并；远端从未发布时，空目录初始化，非空目录必须另外确认「导入本机内容」。解绑明确说明保留工作文件和服务端资料库。 | 文件系统不支持、名称冲突或目录已同步时，说明原因，允许重选。取消导入或合并不会开始同步。待发布、待确认或落盘中不提供一键解绑；先处理或查看操作指南。 |
| D3 · P0 同步与生命周期 | 绑定成功后默认开启定时同步，可立即同步、暂停/继续后续轮次。运行时显示「同步中」；完成后显示本次结果和本机时间。冲突按现有规则保留冲突副本。 | **关窗继续，退出停止。** 第一次关窗说明重开和退出入口。再次启动唤起已有窗口；退出停止接单，让当前轮次结束。用户可选择登录系统后启动，默认关闭；首版不要求在系统用户注销后继续同步。 |
| D4 · P0 活动与待办 | 本机近期记录重启后可读；当前待办独立于活动保留期。区分「无待处理操作」「本次同步已完成」「无法联系服务」「需要重新登录」「目录不可用」。 | 没有活动时显示空态；无待处理操作只描述本地状态。目录丢失不自动重建目录或解绑；断网不产生假成功。连续无变化的轮询不刷屏。 |
| D5 · P0 删除保护 | 遵循核心阈值：删除超过 100 个已跟踪路径，或达到跟踪总数的 10%。无需手抄候选前缀。关闭面板、Esc、通知点击、定时重试都不授权发布。 | 要确认的候选已变化时提示「变更已更新，请重新核对」，刷新数量并丢弃旧授权。首版提供计数及工作目录，不承诺列出每个待删文件。 |
| D6 · P0 历史与恢复交接 | 从已绑定库查看**只读主线历史**，支持翻页，看提交、时间与摘要。本机活动不当作版本列表。 | 历史需要联网。已有 CLI 恢复预览待确认时，显示独立的「历史恢复待确认」并引导原操作人回 CLI；不能用删除按钮处理。已确认但中断的工作交现有同步流程继续。 |
| D7 · P0 会话与通知 | 区分退出应用、退出账号和解绑。账号过期则提示重登；退出账号先停止该账号调度，再撤销当前会话，不删除工作目录。系统通知只用于需介入事件，点击回到相应资料库。 | 系统通知不可用时仍可从主窗口处理。注销时离线可先停止本机同步，明确提示远端尚未撤销；重新联网完成注销前不恢复调度。旧凭据已失效且本地、远端未收敛时保留原目录，进入人工恢复指引。 |

**以后再做：** GUI 内历史恢复、逐文件进度与删除清单、多账号同时运行、自动更新、Finder/Explorer/文件管理器徽标。**不在产品范围：** 虚拟盘、共享协作、备份保证、服务端管理。首版不自动接管散落在其他位置的 CLI 状态目录。

## 4. 三端一致的是行为，不是窗口装饰

- **Linux：** 标题栏保留少量操作，资料库列表与详情并排；无 GNOME 托盘扩展时仍可从应用菜单重开，不能把「退出」藏在托盘里。
- **Windows：** 保留系统标题栏、缩放和贴靠；侧栏收起仍可访问三个入口，长路径可查看完整值。系统通知区域与开始菜单能回到同一实例。
- **macOS：** 关闭最后一个窗口不等于退出 App；Dock 重开原窗口。核对面板附属于发起窗口，保留资料库上下文；⌘W、⌘Q 和 Esc 按各自语义处理。
- **三端共同：** 普通操作采用品牌蓝，警示用图标加文字，破坏性操作独立命名。Tab 能走通绑定和核对；打开面板不把删除设为默认动作，取消后焦点回到「查看影响」。状态变化可由读屏读出；200% 缩放下数量、后果和两个按钮均可访问。规范来源与实机检查见[调研矩阵](../research/desktop-platform-design.md)。

## 5. 什么算交付成功

以下是**发布门槛**，不是已测数据。测试使用示例账号和目录，不采集用户遥测。

| 验收 | 给定 / 操作 | 通过条件 |
|---|---|---|
| A1 初次使用（D1、D2） | 新账号无库；创建资料库并绑定。分别演练远端已有内容、显式首次导入、双方非空无基线及不受支持卷。 | 已确认的同步得到预期文件，同名异内容保留两份；取消、拒绝时无误发布或覆盖，提示能引导重选目录。 |
| A2 后台收敛（D3） | 两台设备绑定同库；A 关窗后改文件，B 同步。重开 A，再显式退出。 | B 收到正确内容；A 重开同一窗口无重复任务；退出后不再开启新轮次。三端各做一次关窗方。 |
| A3 删除保护（D4、D5） | 240 个已跟踪路径中移除 82 个；从通知、侧栏、键盘分别打开并取消；再明确确认。另测核对期间本地或 Head 改变。 | 确认前或取消后该删除未发布、另一设备保留文件；明确确认同一候选后才传播。旧候选不授权新变更。 |
| A4 离线与中断（D3、D4、D7） | 断网、令牌失效、暂停、工作目录失联、同步进程中断后重开；外部 CLI 已占锁。 | 对症提示，不伪造进度、不抢锁、不删状态；重连/释放锁后可继续。重新登录不覆盖未同步文件。 |
| A5 活动、历史与隐私（D1、D4、D6） | 查阅本地活动与两页历史，重启；切到另一账号；构造已有 CLI 恢复预览。 | 活动与主线提交分开、待办不丢、不跨账号展示；恢复不会被自动确认。通知/诊断无口令、令牌或完整路径。 |
| A6 桌面可用性（D2–D7） | 用真实安装包、仅键盘、200% 缩放走通主流程；Linux 禁用托盘，Windows 高对比，macOS 测取消与退出。 | 三端均可重新找到窗口、看清风险、放弃或显式完成操作；无一项依赖颜色或托盘。 |

**评审重点：** 是否接受首版单账号、关窗常驻但退出停止、历史只读这三项范围决定。确认后按[技术方案的里程碑](desktop-client-architecture.md#交付顺序与门禁)拆 Issue，而不是按操作系统各做一套客户端。
