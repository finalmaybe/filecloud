# Desktop：按新版设计稿核对

依据：[16 页设计稿](../design/desktop-mockups/filecloud-desktop-design.pdf)。第 2–9 页给出八组界面，第 10–16 页规定操作语义、数据来源和能力边界。核对的是同一任务的入口、选中对象、可执行动作和结果，不要求用户具有稿中那些文件或同步记录。

| 设计页 / 任务 | 发现的差异 → 本次修复 | 验收画面 |
|---|---|---|
| 2 · 资料库工作台 | 行内原来重复显示绑定状态，异常要绕到侧栏处理。现在显示已发布快照的真实大小和项目数，或待删除数量／冲突副本数；「查看」直达对应待办，检查器提供打开目录、更多、同步及暂停后续轮次。 | [工作台](desktop-design/01-libraries.webp) |
| 3、11 · 首次连接与绑定 | 原步骤指示随输入框焦点变化；选错文件夹时正常分支也不方便重选。现在先匿名检查服务，再提交账号；选择目录后检查本机文件系统、读写权限、实际内容和远端发布状态。非空目录首次导入需勾选。此版截图里的「双方非空时禁止继续」已由[和已有文件夹同步](../operations/deployment-and-client.md#和已有文件夹同步)替代：核对后可显式合并。检查结果可滚动，确认按钮留在窗口内。 | [连接](desktop-design/02-login.webp) · [目录检查](desktop-design/02-bind.webp) |
| 4、10 · 文件与快速预览 | 原视图按钮无选中态，文件类型共用图标，预览缺少图片切换、文本行号、PDF 缩放。修复列表／网格切换、文件行菜单、空格预览、图片尺寸与切换、PDF 页码与缩放；文件页保留单返回箭头，切换标签后保留浏览位置。检查器区分资料库快照与本机文件。 | [文件页](desktop-design/03-files.webp) · [PDF](desktop-design/03-pdf.webp) |
| 5、12 · 活动与删除保护 | 原扫描事件在整轮结束后才读出，变更后只显示错误。现在消费真实的扫描完成事件，显示上次成功时间、待核对路径数；右侧确认层显示计数、比例、工作目录与本次候选码。失效可重新核对，必须重新输入并勾选。若旧候选已丢弃，开始新的正常同步是单独的明确操作。 | [核对删除](desktop-design/04-delete.webp) |
| 6 · 冲突副本 | 原「打开」只弹出预览，「打开文件夹」只到库根目录。现在并排显示原文件与保留副本的本机内容、修改时间、大小和差异节选；提供快速预览、复制路径、在文件管理器中定位。支持的常用文档可用本机应用打开；稍后处理不清除待办，标记已整理不移除文件。 | [内容对照](desktop-design/05-conflict.webp) |
| 7、13 · 版本与安全恢复 | 原快照目录逐层替换，未选项目也能预览整个目录，失效后缺少下一步。现在主线／合并来源和可展开的快照树并列，明确选中后才可预览；确认层列出恢复位置、来源、五类影响。可先同步再重新预览，确认不会沿用旧码；单文件版本单独按路径、时间和锚点核对。 | [快照与恢复预览](desktop-design/06-history.webp) |
| 8、13 · 回收站与保留策略 | 原来把目录和名称合成一个输入框，提交后才知道是否重名。现在分别核对目录和恢复名称，按服务端实际规则预检，冲突不能覆盖／合并；版本记录只放回版本列表。到期信息包含剩余天数及日期。回收站与历史独立设置，缩短历史期显示原值 → 新值、快照数、独占内容大小，再核对当前影响。 | [回收站](desktop-design/07-trash.webp) · [保留期](desktop-design/07-policy.webp) |
| 9 · 设置与快捷入口 | 通用页原有重复的会话行和没有详情的版本、后台、检查间隔。现在分组展示，版本信息可打开，自动检查入口通往活动页；快捷窗优先展示运行中的库，其余绑定可滚动查看。重新登录后对之前报凭据过期的绑定执行既有的安全刷新；不能安全刷新时保留原目录。WebDAV 应用密码继续在独立登录的网页管理。 | [设置](desktop-design/08-settings.webp) · [快捷窗](desktop-design/08-quick.webp) |

## 怎样验证

- **界面与交互**：以上截图来自实际构建的 TypeScript 界面。浏览器走查使用隔离的示例数据桥接，未读取用户文件。主窗口为 1440×900，首次连接为 830×450，快捷窗为 340×384；另检查 480×420 文件列表的窄窗布局。实际点击了绑定重选／导入、文件菜单与视图切换、图片切换、空格与 Esc、PDF 缩放、合并来源、候选失效后重新核对、冲突对照、同名改名、保留期取消和快捷暂停。截图中的确认码已遮盖。
- **数据与保护**：在 Linux 本机 ext4 用临时服务、真实 CLI 和两个设备运行 `TestDesktopTwoDevices`（桌面模块 `go test -race -count=1 ./...`）。覆盖未发布／已发布与空／非空目录检查、真实项目计数、删除候选变化、恢复取消与失效、恢复后的设备收敛、冲突副本保留、重名／大小写等价／父路径被文件占用，以及过期的保留期和单文件恢复确认。`TestLocalDocumentAndReveal` 检查本机打开与定位的目标。具体运行方式见[桌面开发说明](../../desktop/README.md)。
- **包与原生窗口**：Ubuntu 24.04 amd64 构建 `.deb` 和 AppImage，比对其中的 CLI 和 GUI 构建 ID。在隔离 Linux 图形会话启动解包后的 AppImage，用临时账号走通检查服务、登录、选择资料库、进入主窗口。浏览器中的快捷窗走查不代替各系统真实托盘、通知权限或文件管理器验收；本轮未在 macOS/APFS、Windows/NTFS 重跑，既有发布门槛见[平台验收记录](desktop-preview.md)。

## 设计交接中的有意区别

- 使用原生窗口控件；不模拟其他平台的标题栏按钮。工具栏的「＋」占位换为绑定目录入口。同步进度条不定量，不显示伪造的百分比、传输速率、剩余时间或逐条删除清单。
- 显示真实设备名（本机）或短设备 ID（只有 ID 的历史提交）。预览读取有上限：文本前 256 KiB、图片和 PDF 最多 12 MiB；更大的文件可下载。可执行文件不通过「打开文档」启动。文件管理器不支持定位时打开所在目录。
- 使用配套服务端可显示完整项目数并在提交前校验恢复位置。旧服务若只有大小则只显示大小；若已有回收站恢复接口但无预检，会提示由服务端在恢复时校验；若连回收站接口都没有，会提示更新服务端。最终是否可恢复始终由服务端在提交时决定。
