# WebDAV 源码版验收记录

## 已验证

- Linux/ext4：用新建测试账号和空资料库启动真实 `filecloud-server`。在 Chromium 登录，进入资料库侧栏「应用密码」，创建凭据。以该凭据写入文件，`filecloud-client library bind` 拉取初版；带 ETag 保存一次，再加锁、重启服务、上传临时稿并用带目标锁的 `MOVE` 替换原件。解锁后原生 `library sync`，工作目录字节与最后保存的版本一致。在浏览器确认撤销，后续 DAV 读取返回 `401`。
- HTTP / SQLite 集成：`go test ./internal/webconsole -run '^TestDAV' -count=1`。覆盖锁定空文件、续租与解锁、目录锁、条件覆盖、跨块 Range、超过 50 项的目录、回收站、传输中断、跨库隔离与同一所有者多凭据。原生候选修改锁定文件返回 `503`，仅删除无关文件可正常发布；网页删除同样尊重写锁。
- Windows 11 来宾：在本地磁盘运行交叉构建的全部 7 个 `TestDAV*` 测试，通过。覆盖文件保存和取回、凭据隔离、锁与条件、完整目录列表、上传期间的并发变化，以及原生和 Web 发布。这部分验证的是服务端处理逻辑。
- 仓库全量 `go test ./...`、`go vet ./...` 通过；Web 控制台、资料库、存储包的竞态检测通过。macOS/arm64 服务端交叉构建通过。

## 小文档保存延迟

开发机 Linux/ext4，本机回环 HTTP、单客户端、已预热，无反向代理。先发布不可压缩的独立数据块，再对同一个文件执行 10 次带强 ETag 的 16 KiB PUT；每次正文不同，计时从发送 PUT 到收到成功响应，不含读取 ETag。1 个小文件；64 MiB 档另有 1 个大文件；256 MiB 档另有 2 个大文件。近邻秩 p95 在 10 个样本中取最大值。

| 资料库中的背景内容 | p50 | p95 |
|---:|---:|---:|
| 0 MiB | 27.6 ms | 32.5 ms |
| 64 MiB | 54.9 ms | 57.3 ms |
| 256 MiB | 138.4 ms | 140.5 ms |

每次 PUT 只发布一个提交；完整快照验证会读盘校验该版本引用的不同内容块。实际编辑器的一次保存可能包含多个请求，应在目标部署上用实际资料库另测。
